# API Overview

The MemorAI REST API provides programmatic access to all platform features. This reference covers authentication, endpoints, request/response formats, and best practices.

## Base URL

All API requests should be made to:

```
https://api.memorai.ro/v1
```

## Authentication

MemorAI uses API key authentication. Include your API key in the `Authorization` header:

```http
Authorization: Bearer your-api-key-here
```

### Getting Your API Key

1. Sign in to [MemorAI Dashboard](https://memorai.ro/dashboard)
2. Navigate to **Settings > API Keys**
3. Click **Generate New Key**
4. Copy and securely store your key

## Request Format

All requests should include these headers:

```http
Content-Type: application/json
Authorization: Bearer your-api-key-here
User-Agent: YourApp/1.0.0
```

## Response Format

All API responses follow a consistent structure:

```json
{
  "success": true,
  "data": {
    // Response data here
  },
  "meta": {
    "timestamp": "2024-01-15T10:30:00Z",
    "requestId": "req_1234567890",
    "rateLimit": {
      "limit": 1000,
      "remaining": 999,
      "resetTime": "2024-01-15T11:00:00Z"
    }
  }
}
```

### Error Response Format

```json
{
  "success": false,
  "error": {
    "code": "INVALID_REQUEST",
    "message": "The request is malformed",
    "details": {
      "field": "content",
      "issue": "Content cannot be empty"
    }
  },
  "meta": {
    "timestamp": "2024-01-15T10:30:00Z",
    "requestId": "req_1234567890"
  }
}
```

## Core Endpoints

### Memories

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/memories` | Create a new memory |
| `GET` | `/memories` | List memories with filtering |
| `GET` | `/memories/{id}` | Get a specific memory |
| `PUT` | `/memories/{id}` | Update a memory |
| `DELETE` | `/memories/{id}` | Delete a memory |

### Search

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/search` | Semantic search across memories |
| `POST` | `/search/vector` | Vector similarity search |
| `POST` | `/search/hybrid` | Combined text and vector search |

### Collections

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/collections` | Create a new collection |
| `GET` | `/collections` | List collections |
| `GET` | `/collections/{id}` | Get collection details |
| `PUT` | `/collections/{id}` | Update a collection |
| `DELETE` | `/collections/{id}` | Delete a collection |

### Real-time

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/realtime/token` | Get WebSocket authentication token |
| `WS` | `/realtime/ws` | WebSocket connection endpoint |

## Rate Limits

MemorAI implements rate limiting based on your subscription tier:

| Tier | Requests/Hour | Burst Limit |
|------|---------------|-------------|
| Free | 1,000 | 100/minute |
| Pro | 10,000 | 500/minute |
| Enterprise | Custom | Custom |

Rate limit headers are included in every response:

```http
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 1642176000
```

## Pagination

List endpoints support cursor-based pagination:

```http
GET /memories?limit=50&cursor=eyJpZCI6IjEyMyJ9
```

Response includes pagination metadata:

```json
{
  "data": [...],
  "meta": {
    "pagination": {
      "hasMore": true,
      "nextCursor": "eyJpZCI6IjE3MyJ9",
      "limit": 50,
      "total": 1250
    }
  }
}
```

## Filtering & Sorting

Most list endpoints support filtering and sorting:

```http
GET /memories?tags=important&type=note&sort=createdAt:desc&limit=20
```

### Available Filters

- **tags**: Filter by tags (comma-separated)
- **type**: Filter by memory type
- **collection**: Filter by collection ID
- **dateFrom/dateTo**: Filter by date range
- **userId**: Filter by user ID (admin only)

### Sorting Options

- **createdAt**: Sort by creation date
- **updatedAt**: Sort by last update
- **relevance**: Sort by search relevance (search endpoints only)
- **title**: Sort alphabetically by title

## Error Codes

| Code | Description |
|------|-------------|
| `INVALID_REQUEST` | Request is malformed or missing required fields |
| `UNAUTHORIZED` | Invalid or missing API key |
| `FORBIDDEN` | Insufficient permissions |
| `NOT_FOUND` | Resource not found |
| `RATE_LIMITED` | Rate limit exceeded |
| `VALIDATION_ERROR` | Request validation failed |
| `INTERNAL_ERROR` | Server error occurred |

## SDK Examples

### JavaScript/TypeScript

```typescript
import { MemorAIClient } from '@memorai/sdk';

const client = new MemorAIClient({
  apiKey: process.env.MEMORAI_API_KEY!
});

// Create a memory
const memory = await client.memories.create({
  content: 'Important meeting notes',
  metadata: { type: 'meeting' }
});

// Search memories
const results = await client.search({
  query: 'meeting notes',
  limit: 10
});
```

### cURL

```bash
# Create a memory
curl -X POST https://api.memorai.ro/v1/memories \
  -H "Authorization: Bearer your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "Important meeting notes",
    "metadata": {"type": "meeting"}
  }'

# Search memories
curl -X POST https://api.memorai.ro/v1/search \
  -H "Authorization: Bearer your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "meeting notes",
    "limit": 10
  }'
```

## Webhooks

MemorAI supports webhooks for real-time notifications:

```json
{
  "url": "https://your-app.com/webhooks/memorai",
  "events": ["memory.created", "memory.updated", "memory.deleted"],
  "secret": "your-webhook-secret"
}
```

### Webhook Events

- `memory.created`: New memory created
- `memory.updated`: Memory modified
- `memory.deleted`: Memory removed
- `collection.created`: New collection created
- `search.performed`: Search operation completed

## Best Practices

### 1. API Key Security
- Store API keys in environment variables
- Use different keys for development and production
- Rotate keys regularly
- Never commit keys to version control

### 2. Error Handling
- Always check the `success` field in responses
- Implement retry logic for rate limit errors
- Log `requestId` for debugging support issues

### 3. Performance
- Use pagination for large datasets
- Implement client-side caching where appropriate
- Batch operations when possible
- Use appropriate timeout values

### 4. Rate Limiting
- Monitor rate limit headers
- Implement exponential backoff
- Cache responses when possible
- Consider upgrading for higher limits
